# M1 Census III corpus — npm
#
# 100 targets whose NAMES come from Census III of Free and Open Source Software (Linux Foundation
# Research, OpenSSF and the Laboratory for Innovation Science at Harvard, December 2024), Appendix
# A: Top 500 npm, Direct, Version Agnostic Packages. Taken from the report's own published dataset,
# the eight appendix CSVs deposited on Zenodo at DOI 10.5281/zenodo.21110566 — not from the PDF and
# not from a downloads chart. Census III ranks by what the SCA vendors (FOSSA, Snyk, Sonatype, Black
# Duck) observed real codebases depending on, which is a different population from "what npm serves
# the most tarballs for".
#
# This corpus answers a different question from m1-npm-common.txt. That one is stratified by build
# system so that a bad rate on one kind of package cannot hide inside an aggregate. This one is a
# popularity list, and popularity does not distribute itself evenly across build systems.
#
# SAMPLING — the census rank order was modified, and here is exactly how:
#
#   Walk Appendix A in census rank order. Keep a name if m1-npm-common.txt does not already have it
#   (matched on name, not version). **Cap each npm scope at 5 targets**; unscoped packages are
#   uncapped. Stop at 100. That runs from rank 7 to **rank 191** of 500 and skips 43 names that hit
#   the cap: 40 @jupyterlab/* and 3 @angular/*.
#
# The cap is not cosmetic and the file would mislead without it. Uncapped, the first 100 new names
# include 32 @jupyterlab/* packages, clustered at ranks 82-141 on identical z-scores, because the
# scans see one JupyterLab install as several dozen separate direct dependencies. Thirty-two
# packages out of one monorepo are one toolchain and one build config: if it reproduces we book 32
# successes, if it does not we book 32 failures, and the headline rate swings 32 points on one
# project. That is one data point counted 32 times, not 32 measurements — exactly the failure mode
# m1-npm-common.txt's build-system stratification exists to prevent. Capping at 5 keeps the signal
# that JupyterLab is heavily depended upon without letting it set the rate.
#
# Scopes at or near the cap after sampling: @jupyterlab 5, @angular 5, @types 3, @testing-library 3,
# @emotion 2, @salesforce-ux 2. Anyone quoting a rate off this file should know the ordering was
# modified; an undocumented cap would be worse than the concentration it fixes.
#
# **Every entry was resolved against the registry on 2026-09-19**, taking dist-tags.latest from
# registry.npmjs.org. A version that does not exist is not a failing target, it is a permanently
# depressed rate with no way to tell: the run reports it as unresolvable for ever and nobody
# rechecks a corpus. Across ranks 7-191 no name was unknown to the registry, none had been
# unpublished, and none had a pre-release latest, so nothing was dropped between census and file.
